## 3. 功能实现详情

### 3.1 PluginBase - 插件基类

- **职责**：所有插件的抽象基类，定义统一接口
- **核心功能**：
  - 插件元数据声明（`metadata`）
  - 生命周期方法：`initialize()`、`startup()`、`shutdown()`
  - 状态回调：`on_enable()`、`on_disable()`
  - 上下文管理：`set_context()`、`get_context()`
  - 状态属性：`status`、`name`、`version`、`dependencies`

### 3.2 PluginManager - 插件管理器

- **职责**：统一管理插件的加载、注册、启用、禁用和卸载
- **核心功能**：
  - `load_plugin()` - 加载单个插件类
  - `load_plugins_from_module()` - 从模块批量加载
  - `load_plugins_from_path()` - 从目录路径动态加载
  - `enable_plugin()` - 启用插件（自动解析依赖）
  - `disable_plugin()` - 禁用插件
  - `unload_plugin()` - 卸载插件
  - `enable_all()` / `disable_all()` - 批量操作
  - 钩子代理方法：`register_hook()`、`execute_hook()`、`execute_hook_chain()`

### 3.3 PluginRegistry - 插件注册表

- **职责**：插件类和实例的中央注册与查询
- **核心功能**：
  - `register()` / `unregister()` - 插件类注册
  - `add_instance()` / `remove_instance()` - 实例管理
  - `get()` / `get_class()` - 按名称查询
  - `list_plugins()` / `list_classes()` - 列表查询
  - `get_by_status()` - 按状态筛选

### 3.4 HookManager - 钩子管理器

- **职责**：提供可扩展的钩子机制
- **核心功能**：
  - `register_hook()` - 注册钩子回调（支持优先级）
  - `unregister_hook()` - 注销钩子（支持按名称、回调、插件名）
  - `execute_hook()` - 并行执行所有回调
  - `execute_hook_chain()` - 链式执行（结果传递）
  - `list_hooks()` / `get_hook_callbacks()` - 查询

### 3.5 插件依赖管理

- **依赖解析**：基于 DFS 的拓扑排序算法
- **自动启用**：启用插件时自动启用其依赖
- **循环依赖检测**：检测并抛出 `PluginDependencyException`
- **缺失依赖检测**：检测未加载的依赖并抛出异常

## 4. 设计原则

遵循第一性原理：
- **原子性**：每个插件是独立的功能原子单元
- **组合性**：钩子是可组合的扩展点，多个插件可注册同一钩子
- **DAG**：依赖关系构成有向无环图，支持自动拓扑排序
- **生命周期分离**：加载 → 注册 → 启用 → 禁用 → 卸载，状态清晰
